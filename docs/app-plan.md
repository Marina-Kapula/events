## Full list

1. Two kinds of users: Student and Admin (one AMFI staff member).
2. Any student can join events and create their own. For their own event, the student is the organizer.
3. The admin invites a student by email and full name. The student gets an email with a link.
4. The student opens the link and sets a password.
5. The password can be changed. A forgotten password can be reset by email.
6. The student fills in the profile. All fields are required:
    - **Photo** — a picture of the student's face, so others recognise them at the meetup.
    - **Nationality** — chosen from a list of countries. Example: Spain.
    - **Age** — a number. Example: 22.
    - **Gender** — chosen from Female / Male / Other.
7. Every student can see other students' profiles.
8. Without a complete profile, a student cannot join or create events.
9. To create an event, the organizer fills in a form:
    - **Title** — a short name. Example: Pizza night at Moschè.
    - **Description** — what will happen, what to bring, who pays. Example: Let's try real Neapolitan pizza and meet new people! Everyone pays for their own pizza.
    - **Photo** — one picture of the place, the food or the activity. Required.
    - **City** — the organizer types the city name. Events can be in any city. Example: Avezzano.
    - **Place** — the street and house number, or the name of the place. Example: Moschè – Pizzeria Napoletana, Via Guglielmo Marconi 41.
    - **Date and time** — the day and the start time. Example: Friday, 20 November 2026, 19:30.
    - **Type** — chosen from the list, or written by the organizer if none fits. Example: Food.
    - **Max people** — how many people can come, the organizer included. Example: 8.
    - **We will speak** — the language of the meetup. Example: English.
    - **Organizer** — filled in automatically.
10. The event types at the start are Meetup, Food, Trip, Sport, Party and Culture. The admin can add a type that an organizer wrote.
11. The organizer counts as one of the people and takes one spot.
12. A draft is seen only by the organizer.
13. An event in review is seen by everyone, marked "not approved". Nobody can join it yet.
14. An approved event is seen by everyone, and people can join it.
15. A rejected event goes back to draft, with the reason. Others don't see it.
16. If an approved event is edited, it goes to review again. Until then everyone sees the old version and new sign-ups are closed.
17. If the admin rejects the changes, the event stays as it was.
18. The organizer can cancel the event at any time, without the admin.
19. Events created by the admin are approved at once.
20. The event list has filters: keyword, city, date, type, size.
21. Past events disappear from the list.
22. Clicking "Join" gives you a spot.
23. A sign-up can be cancelled at any time before the event starts.
24. If there are no spots left, the student asks to join the waiting list. The organizer accepts or declines.
25. When someone cancels, the first person on the waiting list gets the spot.
26. In "My events", under "Created by me", the student sees their drafts, events in review and approved events.
27. In "My events", under "Joined by me", the student sees upcoming events, the waiting list, and past and cancelled events.
28. The admin invites, edits and deletes students. Delete is soft: the student is hidden, their events are cancelled and their sign-ups removed.
29. The admin approves or rejects new events and changes, with a reason.
30. The admin can create, edit and delete any event.
31. The admin manages the list of event types.
32. All notifications go by email and to the site.
33. The organizer is notified when the event or the changes are rejected, when someone cancels, and when someone asks to join the waiting list.
34. People who joined are notified when the event is changed or cancelled.
35. The first person on the waiting list is notified when a spot frees up.
36. The admin is notified about a new event or changes to check.


37. The app language is English.
